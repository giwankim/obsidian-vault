> Slides for a study session on chapter 4, section 13 of a book ("안전한 프로토콜의 설계"), setting the book's step-by-step fixes to a hypothetical payment protocol beside how Toss Payments' real API solves the same problems. Only the identifier slide was captured: the server uses the order number to recognize a resent request as a replay, which raises the question of who should generate that number.
